# 03 — How It Works

## Stage 1: Human Input

The user submits an idea through text or voice.

The system captures:

- Desired city type
- Location or site
- Population
- Area
- Budget assumptions
- Land uses
- Mobility goals
- Environmental goals
- Services
- Special requirements
- User preferences

## Stage 2: AI Understanding

The AI identifies:

- Intent
- Entities
- Constraints
- Priorities
- Missing information
- Conflicts
- Ambiguities

It asks focused clarification questions only when necessary.

## Stage 3: Validated City Brief

The system converts the conversation into a structured planning brief.

The brief becomes the source of truth for later stages and is versioned whenever the user makes a correction.

## Stage 4: Planning and Optimization

The planning layer creates candidate approaches for:

- Land use
- Density
- District structure
- Road hierarchy
- Public transport
- Walking and cycling
- Housing distribution
- Public services
- Utilities
- Green infrastructure
- Environmental resilience

Each candidate is checked against the brief and planning rules.

## Stage 5: Digital Twin

The selected plan becomes a digital representation containing:

- City objects
- Spatial relationships
- Districts
- Parcels
- Roads
- Buildings
- Utilities
- Services
- Metrics
- Scenario history
- Version history

## Stage 6: Web City Visualization

The digital twin is displayed through an interactive browser-based map.

Users can inspect layers, compare versions, view metrics, and explore planning decisions without requiring a powerful computer or game engine.

## Stage 7: Scenario Simulation

The platform tests scenarios such as:

- Population growth
- Increased traffic demand
- Public-transport expansion
- Heat events
- Water constraints
- Utility failure
- Changes in density
- New policies
- Service-demand changes

## Stage 8: Results and Explainability

The system produces:

- Key performance indicators
- Scenario comparisons
- Risks
- Assumptions
- Trade-offs
- Visual evidence
- Recommended actions
- Plain-language explanations

## Stage 9: Human Feedback

The user can:

- Approve
- Reject
- Edit priorities
- Request alternatives
- Add constraints
- Compare versions

## Stage 10: Controlled Learning

Approved outcomes and feedback may improve future recommendations, but only through controlled testing, governance, versioning, and rollback.
